What is Zamboni?

Zamboni is a self-regulating governance framework that keeps your Iceberg table fleet healthy and cost-efficient. It is not a dumb batch script — every table is evaluated through multiple intelligent gates before any operation runs.

🔧

HK Engine

Compaction, snapshot expiry, orphan file cleanup across all production layers.

run_hk.py
🗄️

Archival Engine

Export-then-Delete cold staging partitions to S3 Intelligent-Tiering.

run_archival.py
♻️

Lifecycle Engine

Auto-discover, stale-detect, and clean up non-production tables.

run_lifecycle_*.py

Single EC2 instance runs both the engine processes (triggered by EventBridge) and the Streamlit app (always-on systemd service). The EC2 IAM role (zamboni-ec2-role) provides all required AWS permissions — no per-domain role assumption needed.

EventBridge Scheduling (Phase 1)

💡
Why EventBridge, not Control-M?

For Phase 1 release, EventBridge + SSM Run Command is the simplest scheduling option. The engine evaluates all per-table safe windows and upstream dependencies internally — the scheduler just needs to trigger the engine. Control-M can be added later for dependency chaining without any engine code changes.

Create the following EventBridge rules using SSM Run Command as the target. The HK engine runs every hour but skips tables outside their configured windows.

Rule NameScheduleSSM CommandNotes
zamboni-hkEvery 1 hourpython -m engine.scripts.run_hkSelf-regulates via window_config per table
zamboni-archivalcron(0 4 ? * SUN *)python -m engine.scripts.run_archivalSunday 04:00 UTC
zamboni-nonprod-scancron(0 2 ? * SAT *)python -m engine.scripts.run_lifecycle_scanSaturday 02:00 UTC
zamboni-nonprod-lifecyclecron(0 3 ? * SAT *)python -m engine.scripts.run_lifecycle_cycleSaturday 03:00 UTC
zamboni-nonprod-cleanupcron(0 5 ? * SUN *)python -m engine.scripts.run_cleanupSunday 05:00 UTC
# Create EventBridge rule for hourly HK
aws events put-rule \
  --name zamboni-hk \
  --schedule-expression "rate(1 hour)" \
  --state ENABLED \
  --region us-west-2

# Add SSM Run Command as target (replace ACCOUNT_ID and INSTANCE_ID)
aws events put-targets \
  --rule zamboni-hk \
  --targets '[{
    "Id": "zamboni-hk-target",
    "Arn": "arn:aws:ssm:us-west-2:ACCOUNT_ID:document/AWS-RunShellScript",
    "RoleArn": "arn:aws:iam::ACCOUNT_ID:role/zamboni-eventbridge-role",
    "Input": "{\"commands\":[\"cd /opt/zamboni && python -m engine.scripts.run_hk\"],\"workingDirectory\":[\"/opt/zamboni\"]}",
    "RunCommandParameters": {
      "RunCommandTargets": [{"Key": "tag:Name", "Values": ["zamboni-prod"]}]
    }
  }]'
⚠️
EventBridge → SSM Role

EventBridge needs an IAM role (zamboni-eventbridge-role) with ssm:SendCommand permission and trust policy for events.amazonaws.com to invoke SSM Run Command on the EC2.

Window Configuration Reference

The window_config JSON field in hk_config controls when each table's HK operations are allowed to run.

Type: post_batch

{
  "type":           "post_batch",
  "timezone":       "America/Los_Angeles",  // IANA timezone
  "delay_minutes":  30,    // wait 30 mins after batch end before running
  "duration_hours": 4,     // window stays open for 4 hours
  "blackout_hours": [6,7,8,9,18,19,20,21]  // never run during business hours
}

Type: scheduled

{
  "type":           "scheduled",
  "timezone":       "America/Los_Angeles",
  "days":           ["saturday"],  // run only on Saturdays
  "start_time":     "02:00",       // HH:MM local time
  "duration_hours": 6              // window open for 6 hours
}

Lifecycle Engine Reference

The Lifecycle Engine runs as three separate jobs triggered in sequence by EventBridge.

Job 1 — ZAMBONI-NONPROD-SCAN

python -m engine.scripts.run_lifecycle_scan \
  --environment preprod   # preprod | dev | test
  --dry-run

Job 2 — ZAMBONI-NONPROD-LIFECYCLE

python -m engine.scripts.run_lifecycle_cycle \
  --environment preprod
  --no-dry-run   # sends real SNS notifications when enabled

Job 3 — ZAMBONI-NONPROD-CLEANUP

python -m engine.scripts.run_cleanup \
  --environment preprod
  --no-dry-run   # permanently deletes PENDING_DROP tables
🚨
run_cleanup.py is destructive

This script permanently deletes Glue catalog entries and S3 data for tables in PENDING_DROP state whose expiry window has passed. Always run with --dry-run first and review the output before enabling live runs.

Lifecycle State Machine

ACTIVE └─► (inactive > stale_threshold_days) └─► STALE_CANDIDATE └─► GREENZONE (SNS email sent, 14-day window) ├─► owner exempts ──────────────────► ACTIVE └─► window expired └─► PENDING_DROP (48h final notice) ├─► owner exempts ──────────► ACTIVE └─► window expired └─► DROPPED (Glue DROP + S3 sweep)

Onboarding a New Domain

Register the Domain

Use the Streamlit app → Domain Management → Register New Domain, or via CLI.

# Or via Athena directly (seed script in create_domain_registry.sql)
# New domains inherit the 'default' retention policy

Discover Tables

python -m engine.cli.register discover \
  --db my_domain_db \
  --out my_domain.yaml \
  --domain my_domain

Edit the YAML Manifest

Open the generated YAML and for each table set:

FieldValue
layerstaging | datalake | base | master
tiercritical | standard | low
owner_emailTeam distribution list
ci_numberITSM CI number
policy_templateSTAGING_DEFAULT, BASE_SCD2, etc.
partition_columnpartition_date or business_date

Register Tables

# Dry run first
python -m engine.cli.register bulk --manifest my_domain.yaml --dry-run

# Then live
python -m engine.cli.register bulk --manifest my_domain.yaml --no-dry-run

Validate with Dry Run

python -m engine.cli.dry_run --domain my_domain --verbose

Review gate decisions and SQL previews. Confirm all tables show WOULD RUN for the expected operations.

Enable with Ramp-Up Period

# Set 2-week dry-run-until — HK evaluates but never writes during this period
python -m engine.cli.enable \
  --domain my_domain \
  --dry-run-until 2026-06-30 \
  --no-dry-run

# After 2 weeks — enable for real
python -m engine.cli.enable --domain my_domain --no-dry-run

Monitor

python -m engine.cli.fleet_status coverage --domain my_domain
python -m engine.cli.fleet_status health   --domain my_domain --days 7
python -m engine.cli.cost_report           --domain my_domain
